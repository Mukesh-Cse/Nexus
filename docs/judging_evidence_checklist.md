# Judging evidence checklist

The weights and criteria are taken from the user-supplied prompt, not independently verified competition rules. No score or winning result is promised.

| Criterion | Weight supplied | Evidence available | Gap to address |
|---|---:|---|---|
| Problem understanding | 20% | Specific marine/digital ecosystem; public company/testbed sources; problem_validation.md | Actual member interviews and independent challenge-brief verification |
| Feasibility | 15% | Modular local MVP, requirements, versioned SQLite, setup and fallback demo | Normal server/browser startup in an unrestricted environment |
| Technical quality | 15% | 71 passing core tests, six script-tested views, actual matching and export | Optional LLM credentials; optional library paths; browser QA |
| User value | 20% | Complete discovery/blueprint workflow, feedback input, study protocol | Independent human relevance ratings and measured task value |
| Innovation | 10% | Explicit complementary dependencies, bounded triples and research/funding bridge | Broader domain coverage and ablation evaluation |
| Presentation/demo | 10% | Demo script, exported example brief, labelled limitations | Rehearsed browser demonstration and verified screenshots |
| Partner relevance | 10% | Four member profiles; traceability matrix; public Blue Science Park sources | Member profile confirmation and pilot commitment |

Machine-readable evidence: validation_results.json, ui_test_results.json, live_integration_results.json, startup_attempt.json and scale_benchmark.json. The 40-profile timing is synthetic and excludes external retrieval, asynchronous work and concurrent users.
