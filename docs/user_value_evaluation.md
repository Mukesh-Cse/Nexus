# User value evaluation

## Baseline and proposed workflow

Traditional workflow: inspect member pages, search publications, inspect current call criteria, ask about test facilities, then assemble a brief.

NEXUS-assisted workflow: select company, verify capability evidence, refine a public priority, inspect complementary combinations, review relevance and missing information, export a source-linked first-experiment brief.

This is a proposed workflow improvement. No time saving has been measured.

## Pilot protocol

Recruit company representatives with informed consent. Give each the same discovery task under baseline and NEXUS conditions, counterbalance order and keep the source dataset constant. Record elapsed time, useful opportunities identified, unsupported claims flagged, source inspection rate, relevance ratings and confidence calibration. Use independent reviewers for proposal quality. Preserve unsuccessful attempts and missing ratings.

Primary outcome: relevance judged against a prespecified rubric. Secondary outcomes: task time and evidence quality. A small pilot is descriptive; do not claim causal or statistically generalisable benefits without suitable design.

## Results

No completed human study. No measured time or usefulness differences. Local feedback, if later submitted in the UI, is convenience feedback rather than controlled evaluation.

## Known bias

The synthetic benchmark reflects the authors' concept taxonomy and relationship assumptions. Its metrics verify mechanics; they are not human relevance scores and must not be used to claim market traction.
